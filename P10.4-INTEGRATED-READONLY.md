## Objective

Deliver a cohesive, demonstrable, **non-spending** application architecture:
- a read-only backend API for Cloudflare Workers with D1 persistence, prototyped locally;
- a typed server-side integration from the Next.js app on Vercel;
- an internal authoritative invoice demonstration;
- GitHub Actions CI.

It does not include production deployment, real funds, wallet execution, or a public private-invoice route.

## Architecture

```
Browser ──▶ Next.js on Vercel (server components / route handlers only)
              │  fixture demo (unchanged, demo-only)
              │  internal authoritative demo: off unless DAIDAI_INTERNAL_DEMO=1 and not VERCEL_ENV=production
              │  server-only API client: signs each request (HMAC service key), forwards the viewer session token
              ▼
          Cloudflare Worker (workers/api), read-only
              1. service authentication (HMAC over method, path, timestamp, nonce, body digest; ±60 s; nonce replay window)
              2. request validation (versioned contract, src/api-contract.ts)
              3. viewer authentication (session-token hash lookup) → AuthenticatedViewer (P10.3 brand)
              4. invoice-scoped permission + tenant directory (P10.3 invoiceViewerAuthorizer) BEFORE any invoice read
              5. P10.3 projector over D1 repositories + read-only evidence adapters
              6. response contract (schema v2 projection | uniform error), Cache-Control: no-store, no CORS
          Cloudflare D1 (local prototype only)
              invoices, signatures, sessions, permissions, tenant directory, attempt lineage (same invariants as node:sqlite)
```

### Trust boundaries

| Boundary | Trusted side | Mechanism | Never trusted |
| --- | --- | --- | --- |
| Browser → Vercel | Vercel server | Server-side rendering only. The browser never receives backend credentials. The internal demo is gated by an environment flag and disabled in production | Client-supplied viewer IDs, grants or tenant IDs |
| Vercel → Worker | Worker | HMAC service authentication with a key held as a Worker secret and a Vercel server environment variable (never `NEXT_PUBLIC_*`) | `Origin`-bearing browser requests (rejected), unsigned or replayed requests |
| Worker → viewer | Worker | Session-token hash lookup in D1 with expiry. The session must be issued server-side (no login flow yet) | Wallet connections, invoice approval or consent signatures as identity |
| Worker → data | Projector | P10.3 attested adapters. D1 repositories attest only after re-deriving commitments and validating rows | Source labels, caller-named verifiers |
| Worker → chain | Projector | P10.3 `readOnlyRpc` (four read methods). **No chain reader is configured by default**, so operations stay `unknown/unavailable` | Fixture chain data as authoritative evidence |

### Failure modes and required behaviour

| Failure | Required behaviour |
| --- | --- |
| Missing, invalid, stale or replayed service signature | 401 with a uniform body. No data access |
| Missing or expired viewer session, no permission, or cross-tenant request | A uniform `not-found-or-forbidden`, indistinguishable from a missing invoice. No invoice read |
| Malformed request (ID, version, extra fields) | 400 `invalid-request` before authentication work that touches data |
| D1 unavailable, or a corrupted or tampered row | Fail closed: null projection, or `reconciliation-required` |
| No chain reader, or chain unavailable | Operation `unknown/unavailable`; never settled |
| Duplicate, unknown or hashless attempt; new digest after a final payout | Blocked by both the node and D1 lineage schemas |
| `verified-final` from a caller-supplied verifier name | Refused. Only attested, finalized evidence can record `verified-final` |
| Caching of private responses | `Cache-Control: no-store, private` on the Worker and dynamic, non-cached rendering on Vercel |
| Logs | No tokens, signatures, keys or raw request bodies are logged |
