## Architecture decisions

| # | Requirement | Decision | Why / approval needed |
| --- | --- | --- | --- |
| 1 | Real viewer authentication with a session lifecycle | Server-owned sessions in D1, issued by exchanging a **single-use, short-lived invitation** created by an operator CLI. Sessions have an opaque 256-bit token (stored as SHA-256), a 12 h absolute lifetime, a 30 min idle timeout, rotation on exchange, explicit revocation (logout and an operator revoke), and a per-session record of tenant and viewer. The Vercel server holds the token only in a `__Host-` cookie (HttpOnly, Secure, SameSite=Strict, Path=/) and never exposes it to client JavaScript | There's no identity provider today. An `IdentityProvider` boundary (OIDC/passkeys) is defined so a real provider can replace invitations; choosing and configuring one needs owner approval. The P10.4 environment-variable demo token is **removed** from the authenticated flow |
| 2 | No public preview exposure | Every private page needs a valid session. In addition, private routes return 404 on Vercel **Preview** unless the server variable `DAIDAI_PREVIEW_ACCESS=1` is set **and** a session exists, and on Production unless `DAIDAI_APP_ENABLED=1`. Pages send `noindex` and `no-store` | An environment flag alone never exposes data: a session is always required, and sessions come only from invitations |
| 3 | Global replay protection | A D1 `service_nonces` table with primary key `(key_id, nonce)`. A request claims its nonce with one `INSERT` *after* its signature verifies. A duplicate fails on D1's single primary, so it's consistent across isolates. Old rows are pruned outside the ±60 s window. The per-isolate window remains as a fast path | Tested across **two separate Worker instances** sharing one persisted D1 |
| 4 | Read-only Celo chain reader | `src/celo-rpc.ts`: a JSON-RPC-over-fetch transport behind P10.3's `readOnlyRpc` (4 read methods, with timeouts and size limits), wired into `chain-evidence.ts` adapters. Covers canonical block hash, `finalized` tag, reorg detection by re-reading block hashes, transaction identity, exact cNGN output and the USDt max debit. Configured only by the Worker variable `DAIDAI_CHAIN_RPC_URL` (unset by default) | Tests use a deterministic JSON-RPC server, including reorg, non-final and mismatch cases. An optional manual read-only probe against public Forno is in the docs; CI never uses live RPC. A production endpoint needs owner approval |
| 5 | Claim-time lineage | `src/claim-coordinator.ts`, for an **isolated test environment only**. Steps: preflight → reserve the taker nonce → `recordAttempt` (persisted) → *simulated* dispatch → `recordHash` or `recordOutcomeUnknown`. A `taker_nonces` table (chain, sender, nonce, unique) prevents nonce reuse across invoices. The only dispatcher is `SimulatedDispatcher`, and there is no real dispatcher | Tests cover crashes at each step, concurrent claims, unknown hashes, cross-invoice nonces and duplicate payment |
| 6 | Read-only user flow | `/login` (invitation exchange), `/invoices` (permitted list), `/invoices/[id]` (authoritative view), and `/logout`. Ink and Brass is kept, and the fixture demo at `/` is unchanged. Authoritative evidence is labelled; no synthetic receipt is ever shown as live | Session-gated |
| 7 | Textile requirements | Documented in [Before real Textile FX](#before-real-textile-fx-quote-conversion-and-payout) | Not implemented: needs owner authorization per transaction |

## Trust boundaries (additions to P10.4)

| Boundary | Mechanism | Never trusted |
| --- | --- | --- |
| Browser → Vercel (session) | A `__Host-daidai_session` cookie (HttpOnly, Secure, SameSite=Strict). State-changing route handlers (login, logout) also check `Origin` against the deployment host | Session IDs in URLs; client-readable tokens; cross-site POSTs |
| Vercel → Worker (session ops) | HMAC-signed requests over the body, with the global nonce. `POST /v1/sessions` exchanges an invitation, `DELETE /v1/sessions/current` revokes, `GET /v1/invoices` lists permitted invoices | Unsigned or replayed requests, including across isolates |
| Worker → chain | `readOnlyRpc`, plus timeouts, response size limits and chain-ID checks | Any write or sign method; data from a mismatched chain ID |
| Coordinator → dispatcher | Only `SimulatedDispatcher` exists. Lineage is persisted *before* dispatch | A dispatch without a persisted claim; nonce reuse |

## Failure modes

| Failure | Required behaviour |
| --- | --- |
| Invitation reused, expired, unknown, or for another tenant | A uniform `invalid-credentials`; no session is created; the attempt is rate-limited |
| Session expired (absolute or idle), revoked, or rotated away | `not-found-or-forbidden`, and the Vercel server clears the cookie |
| Nonce replayed on another isolate | 401, because the D1 nonce claim fails |
| D1 nonce store unavailable | Fail closed with 503; never fall back to accepting the request |
| RPC timeout, chain-ID mismatch or oversized response | The operation is `unknown/unavailable`, never verified |
| Reorg (block hash changed) | `reconciliation-required` |
| Crash between claim and dispatch, or after dispatch before the hash | The attempt is retained (`claimed` / `outcome-unknown`), blocks new attempts, and there is no retry |
| Two invoices reserving the same taker nonce | The second is refused |
