## Work allocation / dependencies
Financial path critical: M0 → M1 → M2 → M3. Public UX and evidence structure, user recruitment and provenance review can progress independently; do not merge a conflicting journal/route design. Developer A: canonical mapper, SQLite, state/verification; B (if available): RFQ/RPC/bridge integration; C: public proof, UI, narrative and user coordination. For solo developer, timebox UI until P0 money gates pass. Use existing tests and source, not duplicate application. Every task references R IDs and TESTING evidence. Do not count sponsor documentation as a passing probe.

## Fallback and stop conditions
If RPC method unavailable, try another approved documented provider; if no qualified provider, stop live dispatch and submit only honest control-plane demo if appropriate (not eligible for Textile until live criteria met). If venue has no quote, wait/refresh only before claim, release unused reservation as supported; no unsupported routes. If real user unavailable, do not fake one. If hosted product blocked, retain public static/read-only proof plus local controlled pilot, clearly distinguish them. Cut P1/P2 first; do not cut authorisation, durable claims, finality, safe resumption, real payout or attribution. If deadline cannot be met, disclose missing gate. No second track or rebuild.
