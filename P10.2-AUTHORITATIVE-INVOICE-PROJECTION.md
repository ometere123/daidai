# P10.2 authoritative invoice projection

P10.2 implements the internal, read-only projection planned in [P10.1](P10-AUTHORITATIVE-PROJECTION-PLAN.md). PR #3 was merged at 3aab648d0f68b1295f7e3ef0af14ede7ca3969aa. The registration report, Loops enrollment closeout, and registration execution paths are unchanged.

## Trust boundary

The projection is an internal server query. Authorization must precede repository access. Repository snapshots, independently verified evidence, and canonical chain observations must come from trusted, injectable server ports. This branch does not wire those ports to user-facing routes. It does not expose write-capable SQLite, provider credentials, or operation capabilities.

The existing localhost wallet session and invoice authorization signatures do not establish viewer identity or tenant-specific invoice access. A server-owned viewer and permission mechanism, plus production read adapters, are prerequisites for wiring a route. FixtureWorkspace remains an independent demo-only path. The authoritative display has no route, wallet controls or fixture fallback.

A conversion and payout are distinct operations. A pending, unknown, stale, mismatched or non-final payment cannot establish settlement. A hashless durable attempt is retained for reconciliation. It grants no retry permission.

## Evidence and revision rules

The version 1 wire schema uses canonical decimal strings for atomics and block heights. It validates corridor, token precision, commitment and state consistency. A shape check alone cannot establish authoritative evidence. Trusted server adapters must attest to independently verified transaction envelopes and attribution, then cross-check block hashes and the finalized head through the canonical reader. Tests inject synthetic evidence through those trusted test ports only.

This slice requires the stored attempt and evidence to match the exact projection revision. The current invoice harness increments revisions as operations advance. Before connecting real storage, implement durable same-commitment attempt lineage so each proof remains bound to its recorded attempt revision. Do not relabel earlier attempts with a later revision. Until then, mixed revisions fail closed. Expired authorization also fails closed in this slice.

The Ink and Brass presentation component is internal and has no route. The demo page, CSS and fixture layout are unchanged. Frontend typechecking permits type-only imports of root TypeScript contracts.

## Reproduce

Use Node 22.23.3. From the root run npm ci, npm run typecheck, npm test, and npm run test:browser. The projection tests run as part of npm test and can also be run directly with node --disable-warning=ExperimentalWarning --experimental-strip-types --test test/authoritative-invoice.test.ts.

In apps/web run npm ci, npm run typecheck and npm run test:model. Build with NEXT_PUBLIC_DAIDAI_DEMO_TOOLS=1 using npm run build. Start the built preview with npm run start -- --hostname 127.0.0.1 --port 3219. In a second shell run npm run test:browser. Set DAIDAI_PREVIEW_URL for a different preview port. The preview exercises the existing fixture path, while the internal presentation component is covered by strict TypeScript and build checks.
